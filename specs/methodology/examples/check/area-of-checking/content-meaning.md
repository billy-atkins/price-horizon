## Content Meaning

A rule that the Headings and Captions sections of a style file both use, in a methodology the example invents, standing in a section of its own beside them with the semantic check reading the files for it under it, written whole as a file would hold it:

```markdown
## Titles

### Headings

A heading names what its section holds, in the fewest words that say it.

### Captions

A caption names what its figure shows, then the figure's source after a colon.

### Titles Stay Current

A heading names its section, and a caption its figure, as the file holds them now, never a version gone or one to come, so a reader can trust a title to describe what it titles.

#### Semantic Checks

**Records:**
  - **Name:** title-stays-current \
    **Tests:** each heading names what its section holds now, and each caption what its figure shows now, as the Titles Stay Current rule has it \
    **Reads:**
      - `canon-specs`
      - `application-specs`

    **Carried Out By:**
      - `.ai/skills/check-depot-files/` Title currency

    **Unit:** per file \
    **Candidates:**
      - `.ai/skills/check-depot-files/` `--list-title-candidates`
```

Headings and Captions both use the rule and neither owns it, so it stands in a section of its own beside them, under Titles, the nearest section enclosing both uses, as [`specs/methodology/sourcing-and-citation.md § One Home Per Fact`](/specs/methodology/sourcing-and-citation.md#one-home-per-fact) places a rule several places use. The rule guards that what the specs say is true and current, so its check falls in content meaning, as [`specs/methodology/checks.md § The Areas of Checking`](/specs/methodology/checks.md#the-areas-of-checking) has the area. Whether a title still names what it titles is a judgment the files do not encode, so the check is a Semantic Check, read by an agent a file at a time, its Unit, and guided by the places the invented skill's script lists, its Candidates. The skill's reading Title currency carries it out.
