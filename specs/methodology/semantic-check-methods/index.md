# Spec of Record: Semantic Check Methods

**Reference Key:** File \
**Required:** Description

| File | Description |
|---|---|
| `main.md` | What every semantic check shares: reading the files in full, reading a passage beside its source, using a candidate list, and saying which side a finding's fix goes on. The ways a summary distorts its source, and how a passage still stating wording a change replaced is found. |
| `directory-summary-currency.md` | How a directory's `index.md` and `architecture.md` are read against the files they summarize, and the test for a fact an overview leaves out. |
| `counterpart-currency.md` | How a product file is read against the technical files that build its capabilities, from each side and for an entry that cites nothing back. |
| `scenario-coverage.md` | How a product file's test scenarios are read against the prose they test, both ways. |
| `where-a-rule-lives.md` | How a rule in the wrong file or in two places is found: the inventory made before any judgment, the duplicate inside one section, an outside standard's record, and an overview's restatements, which are no findings. The fix for a real duplicate. |
| `whether-the-home-holds-the-fact.md` | How a cited section is read against what each passage citing it says it states, one cited section at a time, and how a bare citation that needed more is found. |
| `ordinals-and-counts.md` | How each number and each reference to other text is judged. |
| `markup.md` | What no script decides of how Markdown is written, and how it is read. |
| `glossary-terms.md` | How each use of a glossary term and each abbreviation is read against the glossary. |
| `construct-choice-and-form.md` | How a rule's form is judged, a construct or prose, and what the reader asks of each construct that no script decides. |
| `placement.md` | How a directory is read for where its files sit and how they are named. |
| `finished-style.md` | How the prose is read for what a finished spec reads like, and when a listed word or construction is a finding. |
| `agent-agnostic.md` | How the instructions are read for anything that assumes one agent. |
| `skill-form.md` | How each skill, and the checks the canon records, are read for their form. How a kept test is read against the rule for one, a fixture with the tests reading it, found by their `reads` marker, and the index of the fixture files against what its files hold. |
| `diagram-currency.md` | How a diagram is read against its sources and its host file, from its source and from its render. |
| `principles-held.md` | How the files are read against the constitutional principles. |
| `code-against-its-specs.md` | How the application's code is read against the specs it cites. |
| `technical-overview-against-the-code.md` | How the technical overview's account of the code is read against the code. |
